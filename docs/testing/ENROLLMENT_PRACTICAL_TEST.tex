\section{Before You Start}

\begin{itemize}[leftmargin=2em, itemsep=0.2em]
  \item[\chk] \texttt{npm run dev} running; mobile \textbf{Test connection} OK
  \item[\chk] Logged in with enrollment permission (Teacher / Dept Admin / Super Admin)
  \item[\chk] Subject created; section created; teacher assigned to section
  \item[\chk] Enrollment area has even lighting (no strong backlight)
  \item[\chk] Printed or spreadsheet list of student reg\_no values ready
  \item[\chk] Phone battery and storage sufficient for full batch
  \item[\chk] Can verify Supabase: \texttt{students}, \texttt{face\_embeddings}, \texttt{primary-faces} bucket
\end{itemize}

\section{Practical Tips (Reference)}
% ═══════════════════════════════════════════════════════════════════════════

\begin{itemize}[leftmargin=2em, itemsep=0.3em]
  \item Stand arm's-length from student; keep face inside on-screen guide.
  \item Capture \textbf{front} first while student looks at camera lens.
  \item \textbf{Left / right} poses: small head turn ($\sim$30°), not full profile.
  \item Avoid enrolling two students with identical reg\_no — API will reject duplicates.
  \item After each batch, open \textbf{Section Students} and confirm roster count matches log.
  \item If recognition fails for a newly enrolled student, wait 5 sec and retry (FAISS cache invalidates on enroll).
  \item For 50+ enrollments, swap testers or pause every 20 students to avoid fatigue errors.
  \item Log failures immediately in the batch table \textbf{Notes} column (use separate sheet if needed).
\end{itemize}
